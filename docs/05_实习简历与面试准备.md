**个人职责与技术实现：**

## 4. 三个技术亮点

### 亮点一：源码证据链

难点在于模型很容易把未读取内容说成事实。系统用 Workspace 版本、SourceEvidence 行号覆盖和最终中间件复核回答。面试追问通常是“如何处理文件被修改”“为什么引用还会失效”。回答：选区和工具结果都带版本，发送前和最终引用时重新读取；版本不一致就标记 stale 或要求补读。

### 亮点二：受限的 Agent 工具边界

难点不是工具越多越好，而是让工具只读、可观察、可恢复。SourceBackend 拒绝写入/编辑/删除，工具层捕获参数错误，运行事件记录工具调用，LangGraph 检查点支持断线恢复。面试时应区分“模型能调用工具”和“系统会执行任意代码”：本项目只允许受约束的源码工具。

### 亮点三：多语言扩展而非后缀替换

难点在于 C# 的 Roslyn 语义绑定不能直接套给 Python。Python 版本使用标准库 AST，输出真实语法结构，对动态导入和运行时分派保留未知；两种语言共用 Workspace、证据、工具和执行器边界。面试时强调扩展点和不确定性处理。

## 5. 项目讲解稿

### 1 分钟

> 这是一个本地源码分析型 AI 助手，目标是让开发人员在只读工作区中询问业务源码和交接资料。前端是 React，后端是 FastAPI，Agent 运行使用 Deep Agents/LangGraph。模型不是直接接收整个仓库，而是通过源码读取、搜索、知识和记忆工具按需取证；每次读取带文件版本，回答中的源码引用还会经过范围核对。系统保留 C# Roslyn 分析，同时提供 Python AST 静态分析，可以识别 Python 的函数、类、异步方法、装饰器和部分跨文件关系，并且不会执行未知代码。

### 3 分钟

按“前端请求 → FastAPI/队列 → AgentRunExecutor → Workspace 版本读取 → AgentGraphBuilder 装配工具和模型 → 工具调用 → 证据复核 → 事件流展示”讲。强调 SQLite 保存会话和检查点，`SourceBackend` 只读，模型供应商通过配置适配。说明 C# 走 Roslyn helper，Python 走标准库 AST，动态行为明确保持未知。

### 5 分钟核心实现

先讲 `Workspace.resolve/read` 的安全边界，再讲 `source_tools` 如何暴露工具，接着讲执行器如何按后缀预取关系，最后讲 `SourceEvidenceGuard` 如何验证引用。面试官如果追问 RAG，回答“资料检索属于 RAG 风格增强，源码证据是独立的版本化读取链；不能把它们混成向量数据库能力”。

## 6. 十个可能的面试问题

1. **这是普通 LLM 调用还是 Agent？** 是单 Agent 工具工作流；模型可选择工具并循环获取结果，但没有多 Agent 协作。
2. **为什么不能把全部源码一次塞给模型？** 仓库规模、上下文成本和证据可追溯性都不允许；按需读取并登记范围更可靠。
3. **如何防止源码引用造假？** 文件版本、读取范围、行号覆盖和最终中间件检查；仍不等于语义绝对正确。
4. **C# 为什么用 Roslyn？** 需要项目配置、符号、重载和调用关系；文本搜索无法提供这些语义信息。
5. **Python 为什么先用 AST？** 标准库可离线、不会执行代码，足以获得结构；类型推断和运行时分派另行保留未知。
6. **如何处理语法错误？** 返回错误行列和结构化状态，仍可读取文本，但不生成虚假的结构关系。
7. **如何处理模型失败？** 适配层统一错误，运行事件保留失败状态；MCP、Roslyn 和模型分别有降级提示。
8. **是否使用 RAG？** 使用资料和调试记录检索增强；源码主要通过工具读取，不能笼统说全部来自向量库。
9. **为什么不执行用户 Python？** 业务源码可能有副作用和安全风险；本功能目标是静态理解，执行不属于当前契约。
10. **如何测试 AI 功能？** 确定性测试覆盖边界、工具和状态，真实模型只做显式验收；回答质量还需人工抽样，不能只看 pytest 绿灯。

## 7. 需要补课的内容

优先补 Python `ast`、导入系统和类型检查基础；再学习 LangGraph 状态图、LangChain 工具协议、FastAPI 依赖注入、SQLite 事务和异步取消；最后补 C# Roslyn 的语义模型、RAG 评估和 LLM 观测。每个知识点都应在本项目中找到一个真实调用点后再写入简历。
