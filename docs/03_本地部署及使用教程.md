# Windows + VS Code 本地部署与使用教程

## 1. 前置环境

当前脚本要求：

- Windows PowerShell。
- Python 3.12（`backend/pyproject.toml` 限制为 `>=3.12,<3.14`）。
- `uv`，用于按 `backend/uv.lock` 安装 Python 依赖。
- Node.js 22.12 或更高版本、npm，用于安装前端依赖和 Vite 构建。
- 如果要使用 C# 语义关系，需要本机能够下载或已经准备 `.tools/dotnet` 和 Roslyn helper；Python 分析不依赖 .NET。
- 一个可用的 OpenAI Chat Completions、Anthropic Messages 或兼容协议模型配置。密钥只填写在本机设置中。

依赖的用途是：FastAPI/uvicorn 提供服务，SQLAlchemy/Alembic 保存业务数据，Deep Agents/LangGraph 组织 Agent，LangChain 模型适配和工具调用，`tree-sitter-c-sharp` 与 Roslyn 支撑 C# 分析，Python 标准库 `ast` 支撑 Python 分析。

## 2. 首次安装

在 VS Code 中打开仓库根目录 `ARKS-Assistant-master`，在 PowerShell 执行：

```powershell
Set-Location D:\vscode\dsh\akrs\ARKS-Assistant-master
.\Setup.ps1
```

`Setup.ps1` 实际调用 `scripts/dev/Setup.ps1`，依次执行 `uv sync --frozen`、本地知识模型准备、Roslyn 工具准备、`npm ci` 和前端生产构建。网络或语义模型下载暂时不可用时，可以先准备可运行的 Python/前端环境：

```powershell
.\Setup.ps1 -SkipSemanticModels
```

这会使 C# Roslyn 或语义检索进入降级状态；Python AST 的基础解析仍可用。不要把真实密钥写进 `.env`、脚本或 Git。

## 3. 配置模型

启动后进入设置页，选择协议、供应商地址、模型名和 API Key。后端 `ModelSettings` 还会校验上下文长度、输出长度、温度和超时；密钥保存在 `data/settings.private.json`，代码接口返回掩码。

建议先使用较小上下文和低温度验证流程，再按模型能力提高 `context_tokens`。模型配置未完成时，源码浏览和部分本地功能可以使用，但发送真实 AI 问答会失败或进入错误提示。

## 4. 启动与停止

先检查是否已有服务：

```powershell
Invoke-RestMethod http://127.0.0.1:8765/api/health
```

健康检查返回 `ok: true` 时，复用已有服务，不要对同一个 `data/` 再启动第二个实例。没有运行时执行：

```powershell
.\Start.ps1 -NoBrowser
```

脚本会检查 `backend/.venv/Scripts/python.exe` 和 `frontend/dist/index.html`，然后以隐藏窗口启动 uvicorn。默认地址为 `http://127.0.0.1:8765/`。停止由脚本创建的服务：

```powershell
.\Stop.ps1
```

服务日志位于本机 `data/server.stdout.log` 和 `data/server.stderr.log`，不提交到 Git。

## 5. 完成一次 Python 分析

1. 打开浏览器访问 `http://127.0.0.1:8765/` 并登录。
2. 在项目设置中确认源码根目录指向包含 `.py` 文件的目录；当前默认项目使用 `trunk/`。
3. 打开右侧文件树，找到 `example.py` 或项目中的 Python 文件。文件树和搜索不再只限定 `.cs`。
4. 点击文件或选中函数附近的代码，选择“将选区加入对话”。
5. 提问“请解释这个函数的输入、返回值、调用关系和潜在异常，并给出当前源码引用”。
6. Agent 会先读取选区及其上下文；选中 Python 文件时，执行器会尝试调用 `python_relations`，模型也可以主动调用 `python_symbols`。
7. 查看回复中的 `文件:行号` 链接，点击可以回到源码；展开工具调用可检查读取范围和关系分析的 `scope` 说明。

Python 分析是静态分析：它不会导入或执行目标项目。对于动态导入、猴子补丁、反射、运行时装饰器替换和外部包内部行为，回答必须保留“无法从当前源码确定”。

## 6. 如何验证 AI 真的工作

分三层验证：

1. **本地确定性层**：打开 `/api/health`、读取文件、搜索关键词、查看 Python 符号；这些不需要真实模型。
2. **工具链层**：提问需要源码证据的问题，确认事件中出现 `read_source`/`python_relations`，并检查回答引用的路径和行号存在。
3. **模型层**：询问一个代码中有明确答案的问题，再故意追问源码没有的信息；正确结果应明确“当前资料无法核实”，而不是编造。

可使用后端测试验证前两层，真实模型质量需要人工抽样评估，不能用一次成功回复证明整体准确率。

## 7. 常见问题

| 现象 | 排查 |
| --- | --- |
| `请先运行 Setup.ps1` | 检查 `backend/.venv` 和 `frontend/dist/index.html`；必要时重新运行 `Setup.ps1` |
| 端口 8765 被占用 | 先访问 `/api/health`；确认是本项目后复用，否则停止占用进程再启动 |
| 模型连接失败 | 检查协议、base URL、模型名和密钥；不要把密钥贴到对话或日志 |
| Python 文件显示语法错误 | 保留 `syntax_error` 行号，先修复文件或让 Agent 只做文本读取；分析器不会执行文件 |
| C# 关系为 unknown | 检查 `.tools/dotnet` 和 Roslyn helper，缺项目依赖时静态结果可能是 partial |
| 引用提示未核对 | 让 Agent 补读具体行号；当前文件变化后旧引用必须重新读取 |
| 前端知识构建失败 | 在 `frontend` 执行 `npm run knowledge:source-check`，按当前源码重新修订资料 |
| 克隆后没有本机对话 | 这是预期行为；`data/` 和本机密钥不在 Git，需要在新机器重新配置 |

## 8. 最小复现命令

只检查本次 Python 静态分析而不访问真实模型：

```powershell
Set-Location D:\vscode\dsh\akrs\ARKS-Assistant-master\backend
.\.venv\Scripts\python.exe -m pytest -q tests/unit/source_analysis/test_python_analysis.py
```

这组测试会覆盖普通函数/类、异步函数、装饰器、相对导入、局部调用者和语法错误。它不证明模型回答质量，也不执行目标 Python 文件。
