# 后续学习与开发路线

## 1. 第一优先级：把当前系统讲清楚

先不追求增加更多 AI 名词。按下面顺序在本机走通一遍：

1. `Setup.ps1`、`Start.ps1`、健康检查和登录。
2. 从前端文件树读取一个 `.cs` 和一个 `.py` 文件。
3. 观察一次聊天的 `read_source`、搜索和关系工具事件。
4. 打开运行记录，确认源码证据、模型用量和失败提示。
5. 修改一个临时 Python 示例文件，观察版本变化后旧选区如何标记 stale。

完成后你应该能不用看文档解释：请求从哪个 API 进入、哪个模块创建 Agent、工具如何读取文件、回答为什么需要引用。

## 2. Python 分析器的下一步

### 阶段 A：补齐当前静态契约

- 为 `python_relations` 增加 `from module import name` 的目标符号定位，而不仅是文件定位。
- 为 `__init__.py`、命名空间包、`src/` 布局和同名模块增加明确的路径解析测试。
- 对导入循环、条件导入、语法错误和超大工作区增加边界测试。
- 输出关系的 `unresolved_reason`，把“没有同名目标”“动态调用”“外部包缺失”分开。

### 阶段 B：更可靠的项目级索引

- 建立按文件版本缓存的 Python AST 索引，避免每次关系查询重新扫描全部 `.py`。
- 使用 `symtable` 或静态作用域表区分局部变量、全局函数和闭包，减少同名误匹配。
- 对 `self.method()`、类继承和导入别名做候选解析，但继续保留多候选，不假装唯一绑定。
- 如确有需求，再评估 tree-sitter-python、Pyright 或 Jedi；先比较依赖体积、许可证、离线行为和误报率。

### 阶段 C：质量分析

- 增加只读的 Python 规则：未捕获异常、可疑裸 `except`、阻塞调用出现在 async 函数、循环导入和未使用导入。
- 规则结果必须带路径、行号和规则依据，不能把风格建议写成业务 Bug。
- 用人工标注的小型样例集评估结构识别和关系召回，区分静态正确性与模型回答质量。

## 3. Agent 与 RAG 的工程化路线

1. 为工具调用记录统一 trace id、模型版本、输入 token、输出 token、耗时和错误类别。
2. 建立离线问答评估集：问题、期望源码范围、允许的未知结论和禁止幻觉结论。
3. 为知识资料检索增加命中来源、版本和过期状态的可视化；不要只看相似度分数。
4. 对源码证据做“引用有效”和“结论语义正确”两层评估，二者分别统计。
5. 只有当单 Agent 工具边界和评估稳定后，才考虑拆分规划、检索、复核等子 Agent；当前没有必要为了概念增加多 Agent。

## 4. 可靠性与部署路线

- 为模型供应商、MCP、Roslyn 和 Python 分析分别建立超时、取消、重试和降级策略。
- 增加新机器的私有配置向导，但继续禁止在仓库保存真实密钥和 `data/` 数据库。
- 为 `Setup.ps1` 增加离线依赖检查和明确错误分类；目前 `uv sync --frozen`、模型下载和 npm 构建是不同失败点。
- 验证前端生产构建、Windows 隐藏进程、单实例锁和停止脚本的组合行为。
- 对大知识资源考虑 Git LFS 或单独私有对象存储，避免普通 Git 历史持续膨胀。

## 5. 学习计划

### 第 1 周：Python 和现有链路

每天阅读一个真实模块：`workspace.py`、`source.py`、`executor.py`、`graph_builder.py`、`evidence.py`。用自己的话画出一次请求时序图，运行现有测试，不改业务源码。

### 第 2 周：AST 和静态关系

练习 `ast.parse`、NodeVisitor、行号、导入解析、作用域和语法错误；给 Python 分析器增加一个反例测试，确保错误实现会失败。

### 第 3 周：Agent、工具和上下文

理解 LangGraph 状态、工具 schema、检查点、上下文压缩和模型错误。用确定性模型测试，不先消耗真实 API。

### 第 4 周：评估与求职表达

建立 10 个 Python/C# 源码问答样例，记录期望证据范围和允许未知项；再用真实可核实的职责改写简历，避免把自动生成代码写成实习事实。

## 6. 每次修改的交付门禁

1. 先看当前实现和已有测试，确认输入、输出、副作用和未知需求。
2. 小范围修改，不改变 `trunk/`、正式 `data/` 或模型私密配置。
3. 运行相关 pytest、Ruff；前端改动再运行 TypeScript、测试和构建。
4. 记录通过、失败、跳过和未验证范围；真实模型验收单独说明费用和网络依赖。
5. 检查 Git diff、敏感文件和工作区状态，再提交并推送私有仓库。

当前最大技术缺陷是：Python 关系分析已经安全可用，但仍是保守的名称匹配，不能替代完整类型推断；同时真实模型回答质量还缺少系统化离线评估集。下一步最有价值的工作是为这两点补证据和测试，而不是继续堆叠功能名词。
